# M0 implementation plan

Status: Implemented

M0の目的は、一つのmal sourceをRust compilerで検査し、Cへ変換し、host C implementationとlinkして実行できる最初のvertical sliceを作ることである。

## accepted input slice

```text
Unit
Int32
predefined Bool = [Unit, Unit]
n-ary sum, injection, exhaustive case
immutable binding
typed lambda and application
explicit capture list and lexical closure
terminal return
surface if
one Int32/Unit extern operation
main :: Unit -> Int32
```

M0ではString、全整数幅、product generalization、float、self recursion、tail-call optimizationをまだ実装しない。parserとIRは後続追加を妨げない形にするが、未実装syntaxを黙って受理しない。

## work order

1. source file、span、diagnostic、CLI exit code
2. lexerとtoken conformance tests
3. recursive-descent declaration/type parserとPratt expression parser
4. surface AST、name resolution、capture validation
5. alias expansion、structural type equality、M0 type checking
6. `Bool`/`if` desugaring、typed core、ANF
7. closure conversionとprogram-lifetime environment runtime
8. C emitter、generated extern header、C compile/link driver
9. positive/negative fixtureをnative実行するend-to-end tests

各段階は前段の公開data structureではなくtestable behaviorを境界にする。parser recoveryやdiagnostic wordingの高度化は、正しいaccept/reject判定より後に置く。

## compiler layout

```text
compiler/src/
  source.rs       source text, file id, spans
  diagnostic.rs   structured diagnostics
  lexer.rs        tokens
  parser.rs       surface AST construction
  ast.rs          source-oriented nodes
  resolve.rs      names and capture lists
  types.rs        canonical structural types
  check.rs        typed AST
  core.rs         desugared typed core
  anf.rs          ordered intermediate form
  closure.rs      closure conversion
  c_emit.rs       C and extern header generation
  driver.rs       files, C compiler, linker
```

moduleは実装時に必要になった順に追加する。最初から空module群や汎用frameworkを作らない。

## CLI target

```text
malc check program.mal
malc emit-c program.mal --output build/program.c
malc build program.mal --output program --link host.c
malc build program.mal --output program --link libhost.so
```

`--link`は複数回指定可能とする。初期driverはhost C compilerをprocessとして起動する。compiler discovery、default flags、temporary directory policyはdriverに隔離する。

## M0 host example

```mal
extern printInt32 :: Int32 -> Unit;

main :: Unit -> Int32 := \() {
    extern printInt32(42);
    return 0;
};
```

generated headerに対してhost側は概ね次を実装する。

```c
#include "program.mal.h"
#include <stdio.h>

void mal_ext_printInt32(MalContext *context, int32_t value) {
    (void)context;
    printf("%d\n", value);
}
```

正確なinterfaceは[C host ABI](../spec/c-host-abi.md)に従う。

## definition of done

- valid M0 fixtureがparse、type check、C compile、link、executeまで成功する。
- invalid token、syntax、name、type、capture、caseにspan付きdiagnosticを返す。
- evaluationとextern argumentが左から右に一度だけ実行される。
- capturing closureがscope外へescapeし、値を保持する。
- unlisted captureとlambda境界を飛び越すcaptureを拒否する。
- signed `Int32` arithmeticがC undefined behaviorに依存せずwrapする。
- division by zeroと`INT32_MIN / -1`がmal trapになる。
- functionを含むextern signatureを再帰的に拒否する。
- generated Cをwarning有効のClangでcompileできる。
- `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test`が通る。

## non-blocking open questions

Stringという名前、全integer conversion、shift count、full aggregate ABIの改善はM0を妨げない。top-level initializer、trap、lexical detailは[未決事項](../design/open-questions.md)の暫定案をreference compiler profileとして使用し、変更可能なcompiler layerへ閉じ込める。
