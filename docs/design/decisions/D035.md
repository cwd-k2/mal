# D035. operationのpreconditionとruntime failureをauthorityで分ける

- Status: Accepted
- Date: 2026-09-07
- Scope: mal v0.5

## 決定

source programがoperandを構成し、operationを適用するかどうかを決められる場合、値域やindexの条件は
operationのpreconditionとする。precondition違反は言語上のtrapではなく、そのprogramの実行結果を保証しない。
この分類をshift、integer divisionとremainder、floatからintegerへの変換、`Symbol` byte accessとconcatenation、
`Ptr` offsetへ適用する。

operationを実装できるauthorityと、failure policyを選ぶauthorityは分ける。`Symbol`のrepresentationとbyte accessの
mechanismはmalが支配するが、どのindexを渡すかはsource programが支配する。したがってlanguage primitiveだけが
実装できるoperationであっても、範囲検査とtrapを常に強制する理由にはしない。

有効なEngramの構成に必要なstorageをruntimeが確保できない場合は、source-level expressionの現在のresult型では
failureを返せないため、引き続きtrapする。reference count overflowやinternal sum tagの不整合など、特定の
representationだけに由来するfailureはlanguage ruleではなくreference implementationのfatal failureとする。
host adapterが不正なrepresentationを渡した場合はhost contract違反であり、adapterは`mal_trap`へ写像してよい。

compilerはpreconditionを満たすprogramについて規定された結果を生成しなければならない。precondition違反時の
結果を保証するためのruntime checkは不要であり、reference backendが使用するtarget languageの未定義動作を含めて
特定の挙動へ固定しない。

## 理由

trapは終了mechanismであり、authorityの分類ではない。sourceが条件を構成、検査できるoperationへ一律のruntime
checkを入れると、failure policyを言語が引き取り、記述側が既に保証した条件もbackendが再検査することになる。

一方、closureや`Symbol`の内部storageはsourceから直接構成できず、implicitなlambda constructionなどにはfailureを
返す位置もない。このfailureを記述側に移すにはfallible construction、allocator、region、effectなど別の
source-level mechanismが必要であり、既存operationのcheckを外す変更とは分けて判断する。

## 置き換える判断

- [D014](D014.md)の範囲外shift countを一律にtrapする判断
- [D009](D009.md)のfloatからintegerへの範囲外変換をtrapする判断
- [D028](D028.md)の`Symbol` byte accessで範囲外indexをtrapする判断
- [D029](D029.md)の`Symbol` concatenation length overflowをtrapする判断
- [D022](D022.md)のtargetで表現不能なpointer offsetをtrapする判断
- [D033](D033.md)のreference count overflowを言語上のtrapとする判断

各operationの現在のpreconditionとruntime failureは[`spec/`](../../spec/)を正とする。
