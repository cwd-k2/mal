# D056. Cursor loadは値だけを返し、Region indexでlocationを選ぶ

- Status: Accepted
- Date: 2026-09-18
- Scope: external memory access v0.6
- Refines: D052

## 決定

Cursor loadは`<-Cursor<A> -> A`とし、次Cursorをresultへ含めない。Cursor storeの
`Cursor<A> <- A -> Cursor<A>`は維持する。

有限location列から位置を選ぶoperationとして`Region<A> # USize -> Cursor<A>`を追加する。indexは
`index < #region`かつoffset計算がoverflowしないことを未検査preconditionとし、storageをdereferenceしない。
選択した値は`<-(region # index)`で読む。

## 理由

Cursorは一つのlocationを表すimmutable valueであり、loadしても元のCursorは引き続き利用できる。値の観測と次位置の構築を
常にproductへ束ねると、一要素だけを読む通常の用途にも不要なpointer加算とdestructuringを要求する。

反復対象が有限列なら、要素数を持つRegionでbounds preconditionを表し、indexからCursorを選ぶ方が位置指定を直接表せる。
同じbinary `#`でもPacked indexはowned sequenceの要素値、Region indexはexternal locationを返す。operand型によりresultが
静的に決まるため、新しいruntime dispatchは導入しない。

storeが次Cursorを返す規則は連続初期化のchainに利用でき、loadのresult shapeと一致させるためだけに削除しない。

## 帰結

- 一要素loadは`value := <-cursor`となる。
- Region内の任意要素は`cursor := region # index`で選び、loadとstoreの双方に使える。
- Regionを持たない連続readで次位置が必要なら、Address offsetとplacementで明示的に構成する。
- backendのCursor loadは値のloadだけを出力し、次pointerとproductを生成しない。

現在の規範は[external memory](../../spec/memory.md)と
[`Region`と`Packed`](../../spec/packed.md)を正とする。
