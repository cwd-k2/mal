# D063. non-growing Buffer helperへactive dataを渡す

- Status: Accepted
- Date: 2026-09-19
- Scope: reference LLVM backend

## 問題

`Buffer<A>`はsource上の一つのscoped authorityだが、通常のinternal ABIでbuilder pointerを渡すと、helper内の`get`と`put`はactive dataを
builder slotから繰り返し読む。helperとその呼出し先がgrowthを行わない場合、この間接参照はruntime representationだけに由来し、素直な
helper分割の性能を損なう。

## 決定

`backend/llvm/optimization/buffer_abi`を任意のLLVM techniqueとする。Buffer parameterを持ち、到達するcontrolとcall targetが
`get`と`put`だけを行うinternal functionでは、そのBuffer leafをactive data pointerとして渡す。product以外に埋め込まれたBuffer、
Buffer resultまたはcapture、表現が混在するindirect call、同じrecursive region内で表現が一致しない候補は通常ABIへ残す。

candidate集合はlocalな型とoperationのadmission後、application graphとrecursive regionについて閉じる。call emissionだけが選択済み境界で
builder pointerとactive dataを変換し、execution planとownership planは変更しない。

## Authorityからの導出

`Buffer<A>`のscopeとoperationは仕様、operationを含むcontrolとpossible targetはexecution、growthとactive data slotはruntime、internal
representationはLLVM backendが所有する。backendはこの四者のfactから移動しない区間だけを選べるが、builder identityやdata stabilityを
言語またはexecutionのfactとして追加できない。

## 帰結

- growth可能なhelperはbuilder ABIを維持する。
- selectionを無効にしたbaselineも同じobservable resultを返す。
- representational shapeとprogram graph closureを別moduleで判定する。
- active data loadへC runtimeと共有できないalias metadataを付けない。
