# D071. crateを利用者の層で分けてcommandを整理する

- Status: Accepted
- Date: 2026-09-24
- Scope: repository structure and `malc`

## 問題

単一のcompiler crateにfrontend、lowering、LLVM生成、driver、formatter、editor indexが同居し、外部依存を持つlanguage serverだけが別crateだった。
分離の基準が「外部依存の有無」であり、機能の層とは一致しなかった。language serverはfile読み込みのために、Clangを起動するdriverを含むcrate全体へ
依存していた。commandは生成系が`emit-*`と`build`に混在し、出力先の規則も揃っていなかった。

## 決定

Cargo workspaceを`crates/`に置き、crateの境界を「その層だけを必要とする別々の利用者がいるか」で引く。

- `mal-syntax`: source、diagnostic、lexer、AST、parser、source graphの読み込み。
- `mal-fmt`: formatterと`mal-fmt` command。
- `mal-frontend`: resolve、check、specialization、editor index、analysis。
- `mal-backend`: core以降のlowering、execution plan、LLVMとC生成、C11 runtime。filesystemもprocessも扱わない。
- `mal-compiler`: `malc`のcliとdriver。
- `mal-lsp`: language server。外部依存を持つ唯一のcrate。

`malc`のcommandは`check`、`build`、`emit header|host|atcoder`とする。`emit`は`-o`がなければstdoutへ出し、`build`は`-o`を必須とする。
formatterは`malc`から外し、`mal-fmt`が担う。

## 帰結

- formatterとlanguage serverはbackendとClangの依存を引かない。
- `malc emit-header`の既定出力（sourceと同じdirectoryの`program.mal.h`）は廃止し、stdoutまたは`-o`にする。
- 詳細な責務は[compilerの責務境界](../../implementation/responsibilities.md#crate構成)を正とする。
