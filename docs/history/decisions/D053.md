# D053. managed byte値をC host ABIへ公開しない

- Status: Accepted
- Date: 2026-09-17
- Scope: reference C host ABI v0.6

## 決定

public C ABIとgenerated headerへ出せるmal typeを`HostMappable` judgmentだけで決める。`Symbol`、`Packed`、`Region`、
`Cursor`、functionはHostMappableではなく、これらを含むproductとsumも公開しない。

可変長bytesはoperation固有の`Address`と`USize`または`ByteSize`で渡す。malからhostへ出す場合はmalがexternal
storageへbytesを書いてから、その範囲をcall中だけ貸す。hostからmalへ入れる場合はhostがmalから借りたwritableな範囲を
初期化し、malがRegionからPackedまたはSymbolへadmitする。Addressのreferent ownership、permission、範囲、lifetimeは
operation固有のcontractに残り、hostはcall後にAddressを保持しない。

この変更はpublic ABIを`0x000800`へ上げる。public headerはHostMappableなbuiltin carrierとhelper、およびextern surfaceから
到達できるHostMappableな型だけを生成し、mal内部のmanaged carrierやownership operationを宣言しない。

## 理由

`Symbol`と`Packed`と`Region`の間に明示的なadmissionとobservation境界があるため、managed byte値をABIへ直接写す必要はない。
Addressを使うcall-scoped borrowへ統一すると、Engramのownership authorityをmal内に保ったまま、hostとのbyte transferを
external memoryのcontractだけで記述できる。

`HostMappable`を唯一の公開条件にすれば、checker、generated header、C bridgeの責務が一致する。Symbol専用descriptor、span、
materialization、copy、retain helperを公開する必要がなくなり、新しいmanaged typeが暗黙にABIへ入ることも防げる。

## 採らない案

- `Symbol`だけを特別なhost descriptorで公開する: HostMappableの境界とmanaged ownershipの境界が一致しない。
- `Packed<UInt8>`をborrowed spanとして公開する: source typeにない連続性とborrow lifetimeをABI representationへ加える。
- `Address`だけを渡して長さを暗黙にする: 範囲を表せず、終端byteや固定長というoperation固有の仮定を共通ABIへ持ち込む。
- hostが返したAddressをSymbolから継続して参照する: Engramのlifetime authorityをhost storageへ依存させる。

この判断は[D040](D040.md)のSymbol mappingを置き換える。typed host value、call capability、terminal returnに関するD040の
判断は維持する。現在の規範は[C host ABI](../../spec/c-host-abi.md)と
[`extern`](../../spec/extern.md#host-mappable-type)を正とする。
