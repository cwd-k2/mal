# D051: lambdaとresult boundaryのarrowを分離する

Status: Accepted (2026-09-14)

## 決定

`->`はfunction typeとlambda parameterからbodyへの境界だけに使い、direct result blockは`[result, ...] => body`と書く。
lambda固有のreturn binder groupは廃止し、early resultまたは直和構築が必要なlambdaはbody全体にdirect result blockを置く。

```mal
absolute :: Int32 -> Int32 :=
    (value) -> [return] => {
        when (value >= 0) return(value);
        return(-value)
    };
```

lambda bodyは期待result型`B`の`Value(B)`だけでなく`Abrupt`でもよい。これにより正常にはreturnしないfunctionをresult型に
かかわらず表せ、`A -> []`のためだけのempty return binder groupを必要としない。direct result blockは従来どおり一つ以上の
binder、期待result型、すべてのreachable pathでの`Abrupt` completion、自身のbinderを使うreachable pathを必要とする。

## 理由

lambda return binderとbody全体を囲むdirect result blockは同じ結果を表せる一方、別々の構文、scope、型検査、editor metadataを
必要としていた。functionの通常result edgeはlambda bodyの`Value` completionとして既に存在するため、名前を付ける専用機構を
残さず、必要な箇所だけ既存のlexical result boundaryを合成する方がsystem全体の独立contractを減らせる。

`->`と`=>`を分けることで、`(parameter) -> [result] => body`はlambdaのbodyにresult blockを置いた構造として局所的に読める。
`(parameter) -> body`を省略構文とはせず、lambdaとresult blockのgrammarを独立に保つ。

## 置き換える判断

[D050](D050.md)のterm位置に同じ`->`を使う判断と、lambda return binderを維持する部分を置き換える。
[D049](D049.md)のdirect result blockをfunction valueではなくlambda-local joinとする判断は維持する。
現在の規範は[式とbinding](../../spec/expressions.md)、[result boundaryとcompletion](../../spec/control.md)、
[字句と文法](../../spec/grammar.md)を正とする。
