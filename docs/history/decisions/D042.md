# D042. applicationをvalueとcontinuationの双方向表記に統一する

- Status: Accepted
- Date: 2026-09-10
- Scope: mal v0.5 source language

## 決定

通常のapplicationには、continuationを先に書く`f(a)`とvalueを先に書く`a[f]`を認め、同じtermへ正規化する。
applicationは表記にかかわらずvalueを先に、continuationを後に評価する。`f()`、`()[f]`、`[f]`は`Unit`を
渡す同じapplicationである。

複数のcontinuationを持つ`value[f, g, ...]`は直和の除去とする。scrutineeを一度評価してからactive variantに
対応するcontinuationだけを評価し、payloadへ適用する。continuation数は直和の項数と一致し、各parameter型は
対応する項型、result型はすべて同じでなければならない。一項の`value[f]`は通常のapplicationであり、別の
control constructにしない。

```mal
apply :: (Int32 -> Int32, Int32) -> Int32 := (continuation, value) {
    continuation(value)
};

result := value[first, second];
composed := value[f][g];
initialized := [initialize];
```

直和injectionの第`i` constructorは`i[Sum]`または`Sum(i)`で選び、対応する項型から直和型へのfunction valueを
得る。通常のapplicationでpayloadを渡すため、`i[Sum](payload)`と`payload[i[Sum]]`は同じtermである。Unit項も
例外にせず、`0[Bool]()`、`()[0[Bool]]`、`[0[Bool]]`を同じ値とする。indexはruntime整数ではなく、範囲内の
compile-time integer literalでなければならない。

```mal
Bool :: [Unit, Unit];
false :: Bool := 0[Bool]();
true :: Bool := 1[Bool]();

MaybeInt32 :: [Unit, Int32];
none :: MaybeInt32 := 0[MaybeInt32]();
some :: Int32 -> MaybeInt32 := 1[MaybeInt32];
```

lambda introducerの`\`とsource-level `case`を削除する。lambdaは`(pattern) { ... }`で導入し、直和除去は
continuation applicationだけで表す。`if`は頻出するBool除去のsurface syntaxとして残す。reference compilerは
直和除去と`if`を既存のtyped case representationへlowerしてよく、backendのtag dispatchはsource syntaxの
削除によって変わらない。

## 理由

function application、Unit application、関数合成、直和除去をvalueとcontinuationの一つの関係として読める。
従来のcase arm indexはexhaustiveな直和除去で型の項順を繰り返しており、位置付きcontinuationなら重複、欠落、
並べ替えをarityと型から直接検査できる。branch blockはlambdaとして通常のfunction valueと同じ語彙になる。

`f(a)`と`a[f]`を作用を含む任意のexpressionで同一にするには、字面上の順序から独立した評価規則が必要である。
value-firstなら後置形、関数合成、直和scrutinee、`if` conditionを同じ順序で説明でき、選ばれないcontinuationの
作用を実行しない従来のbranch semanticsも保存できる。

Cの`a[i]`と`i[a]`はpointer additionの可換性から同じになるが、malの二表記はそのようなoperand operationへ
依存せず、型がvalueとcontinuationの役割を決めた後に同じapplicationへ直接正規化する。

## 置き換える判断

D004の直和型notationとordered n-ary sumは維持するが、`T[i](value)` injection spellingを置き換える。
D005のBool表現、`if`、論理operationは維持し、`case`へのsource-level説明をcontinuation applicationへ置き換える。
D023のsource-level `case` syntaxはこの判断が置き換える。
