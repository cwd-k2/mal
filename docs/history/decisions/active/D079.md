# D079. Buffer座標をphantom `Index<T>`で記述する

- Status: Accepted
- Date: 2026-09-28
- Scope: language, compiler, editor tooling, and Buffer API

## 問題

Buffer上のtree、DAG、graphは要素間の関係を`USize`座標で表せるが、型とeditor表示から参照先の要素型が失われる。
一方、座標をnominal typeにすると、既存の整数演算やBuffer operationとの互換性がなくなり、異なるBuffer identityや範囲を
型だけで保証できるという誤った期待も生む。recursive row型からchild座標を参照する場合、通常のgeneric alias展開では
表現に寄与しない型argumentまで辿ってrecursive value typeとして拒否していた。

## 決定

`Index<T> :: USize`に相当するpredefined transparent aliasを導入する。`T`は表現に寄与しないphantom parameterであり、
`Index<A>`、`Index<B>`、`USize`は同じcanonical typeとする。Buffer operationのsource signatureでは要素位置を`Index<T>`、
count、capacity、length、external storage offsetを`USize`で記述する。

generic aliasの型parameterが右辺へ直接現れない場合、そのparameterに対応するargumentをcanonical representation dependencyとして
展開しない。別のalias applicationのargument位置へ現れたparameterは直接使用とみなし、参照先aliasによる消去を逆向きに伝播しない。
editorはcanonical typeだけへ潰さず、`Index<T>`のsource spellingとphantom argumentの参照identityを保持する。

## 理由

このaliasはruntime representation、整数operation、Buffer ABIを変えずに座標の意図とdefinition navigationを残す。
phantom判定をdeclarationごとに局所化すれば、別aliasの変更によってcycle判定が暗黙に変化しない。

## 非目標

`Index<T>`はBuffer identity、範囲、root、acyclic性、row間のdomain invariantを証明しない。これらはconstructorとvalidatorが所有する。
現在のmodeling guidanceは[indexで結ぶBuffer構造](../../../design/indexed-buffer-structures.md)を正とする。
