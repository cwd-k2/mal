# D096. Buffer handleをStorableにする

- Status: Accepted
- Date: 2026-10-03
- Scope: language、frontend、reference LLVM backend
- Refines: D075

## 問題

D075は`Storable`をmal-ownedなimmutable valueの集合として導入し、`Buffer<Buffer<A>>`を除外した。しかしBuffer element storageが
必要とする条件はimmutabilityではなく、carrierを保持し、readでShareし、replaceと終了でDropできることである。現行backendは
Buffer handleを通常値としてretain/releaseし、managed Buffer element callbackも同じ再帰処理を使う。除外はlifecycle能力ではなく、
handle aliasが変更を共有観測することを理由にしていた。

Pool案でIxPool handleをplaceへ保存可能にすると、primitive Bufferだけが同じ種類のhandleを保存できない二つのstorage modelになる。
一方、external opaque carrierにはruntime-ownedだがlifecycleがTrivialなstorage分類がまだなく、functionにはhidden captureによるcycleの
問題が残る。これらを一つの緩和として扱うと、意味と実装の依存が混ざる。

## 決定

`Storable(Buffer<A>)`を`Storable(A)`のとき認める。nested Bufferの`get`、`new`、`put`、`fill`、`copy`はBuffer handle carrierの
shallowなoperationであり、内側identityをdeep copyしない。同じhandleを複数のplaceへ保存した場合、どのhandleからの変更も同じ
referentを指すhandleから観測できる。外側placeのreplaceはhandle carrierだけを置き換える。

Buffer storageは格納したhandleをretainし、read resultのresponsibilityをShareし、上書きと外側Bufferの終了でDropする。
canonical memory representationは追加しないため、nested Buffer elementは`from`、`into`、canonical memory helperには使えない。

function、external opaque type、empty sumは引き続きStorableでない。external opaque carrierは`Runtime(_, Trivial)` storageを実装・検証する
後続decisionへ分ける。

## 理由

- shared mutable identityはBuffer自身が既に持つsource semanticsであり、place admissionから除外する理由にならない。
- Buffer handleの入れ子に専用のdeep-copy規則、exclusive authority、`Stable` judgmentを追加せず、通常のhandle semanticsだけで説明できる。
- Bufferを含むrecursive value typeは形成できず、file-local opaque representationの再帰も拒否される。finiteな型構造を辿る
  reference-counted owner edgeだけが増え、function captureのような型から見えないback-edgeは増えない。
- backendのruntime value layout、Buffer handleのretain/release、managed element callbackを再利用でき、Pool用の別lifecycle機構を
  作らずに境界を先に検証できる。

## 帰結

- `Storable`はimmutable-value分類ではなくplace lifecycle admissionになる。`Managed`はShare/Drop glueが必要なcarrierの実装分類であり、
  `Storable`の別名にはしない。
- LLVM Buffer storageはnested Bufferをruntime-owned elementとして扱う。C runtimeのmanaged entry pointとcallback ABIは変えない。
- genericな`Buffer<A>`が要求する`Storable(A)`は、concreteな`A = Buffer<B>`について`Storable(B)`へ再帰する。
- `Buffer<Buffer<A>>`のalias、growth、上書き、重なるcopy、終了をAddressSanitizer下でbaselineとproductionの両方について検査する。
