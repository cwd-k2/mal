# D085. operation familyへ非重複なgeneric implementation patternを導入する

- Status: Accepted
- Date: 2026-09-28
- Scope: language and compiler

## 問題

exact implementationだけでは`Buffer<A>`やproduct shapeに共通するoperationをconcrete element型ごとに反復する必要がある。
specificityやsource-order priorityを導入すると、別fileへのimplementation追加によって既存goalの選択が変わる。

## 決定

family declarationの型parameter名を再利用するcanonical type patternをimplementation keyに認める。全parameterをkeyで束縛し、
catch-all patternを拒否する。二つのkeyが同じconcrete goalへunifyできるprogramは拒否し、exact keyにも優先順位を与えない。
generic implementationが生むoperation requirementはkeyのproper structural subtermへ減少させる。同じfamily、同じkeyの直接再帰だけを例外とする。

## 理由

非重複をprogram-wideに検査すれば選択は一意で、型argument推論をimplementation集合から独立に保てる。減少条件によりrequirement展開は
有限になり、選択後は既存のspecializationと単相backendをそのまま使える。

higher-kinded type、specificity、runtime dictionaryは導入しない。現在の規則は
[operation family](../../../spec/operation-families.md)を正とする。
