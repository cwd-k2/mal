# D094. implementation keyを型patternとして読む

- Status: Accepted
- Date: 2026-10-01
- Scope: operation familyのimplementation key
- Refines: D086

## 問題

implementation keyのbinderはfamily declarationの型parameter名に限られ、constructor-kind位置のkeyはclosed constructor termに
限られていた。`pure<F, A> :: A -> F<A>`を`Either<E>`について一度だけ実装するには、keyの中で`E`を束縛し、`Either`を`E`へ
部分適用したtermをconstructor位置に置く必要があるが、どちらも書けなかった。`E`ごとに`Either<Symbol>`のような
implementationを並べるしかなかった。

## 決定

implementation keyを型patternとして読む。型applicationの先頭以外に現れ、見える型名に解決しない名前はpattern変数として
そのimplementationのbinderになる。constructor-kind位置には、opaque typeまたは`Buffer`をpattern変数を含む引数へ部分適用した
termを認め、先頭のdeclaration identityで一次に照合する。constructor自体をpattern変数にするkeyと、transparent aliasを先頭に
持つpattern変数入りのkeyは拒否する。規則は[operation family](../../../spec/operation-families.md)に置く。

## 理由

- 構文を加えない。値のpatternが宣言なしに名前を束縛するのと同じ規則を、型のkeyへ当てはめる。
- 照合はspecializationの選択だけで行い、call siteの推論はfamily signatureと引数だけを使う。implementationを推論の
  情報源にしない性質は変わらない。
- 先頭をnominalなconstructorに限るため、照合は先頭の比較と引数の一次照合で終わる。transparent aliasは展開後のtermから先頭を
  一意に決められず、[D086](D086.md)が避けたhigher-order unificationになるので、pattern変数入りのkeyの先頭にしない。
- 見える型名に解決する名前はその型を指すため、型parameter名を型名と区別する[D089](D089.md)の性質は保たれる。

## 結果

型名の書き損じはpattern変数になり得る。値のpatternで名前を書き損じた場合と同じ性質であり、重なる別のimplementationがあれば
coherence検査で拒否されるが、重ならなければ全ての型へのimplementationとして受理され、誤りはkeyから離れた箇所に現れる。
この代償を受け入れ、書き損じの候補はdiagnosticのnoteで示す。型変数を字面で区別する案は
[型変数を字面で型名と区別する案](../../../proposals/type-variable-spelling.md)で検討する。
