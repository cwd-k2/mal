# D091. 実行可能programのcheckはspecializationまで行う

- Status: Accepted
- Date: 2026-09-29
- Scope: `malc check`、language server diagnostics

## 問題

`malc check`とlanguage serverは型検査で止まっていた。到達したoperation keyのimplementationがない、specialization nodeの
上限を超えるなど、仕様がcompile-time errorとするがspecializationで初めて分かる誤りは、`check`とeditorでは報告されず、
`build`だけが失敗した。

## 決定

root fileが`main`を宣言する実行可能programでは、`malc check`とlanguage server diagnosticはspecializationまで行い、その
source errorを報告する。`main`のないlibrary fileは従来どおり型検査までとする。language serverは型検査に成功したprogramの
editor queryを、specialization errorがあっても提供する。規則は[`malc`利用contract](../../../development/compiler-usage.md#check)に置く。

## 理由

- `check`が成功したsourceは、target固有のartifact admissionを除いて`build`でも受理されるという期待に合わせる。
- specializationはentryから到達するkeyを定めるので、entryのないlibraryには適用できない。libraryの誤りはそれを使う
  programの`check`で報告される。
- specialization errorは型検査済みprogram上の誤りであり、hoverや定義位置などのqueryを止める理由にならない。
