# D082. `Symbol`を`/`と`%`でbyte位置分割する

- Status: Accepted
- Date: 2026-09-28
- Scope: mal v0.6 and reference compiler

## 決定

`value / index :: Symbol`を先頭`index` bytes、`value % index :: Symbol`をoffset `index`以降のbytesとする。
operand型は`Symbol / USize`と`Symbol % USize`で、`index <= #value`をpreconditionとする。両operatorは既存の
[multiplicative precedenceと左結合](../../../spec/grammar.md#operator-precedence)を保つ。precondition違反は
[D035](D035.md)に従って実行結果を保証しない。

二つの結果は`(value / index) + (value % index) == value`を満たす。左結合により、`value / end % start`は
range `[start, end)`、`value % start / length`はrange `[start, start + length)`を表す。端点0と`#value`を認め、
空rangeと値全体を追加の特例なしに得られる。

結果は独立したimmutableなbyte値であり、storage identityを公開しない。reference runtimeはnon-emptyな結果を元のbyte ownerを
retainしたrange view、emptyな結果をownerを持たないcanonical emptyとして実装し、bytesをcopyしない。

## 理由

`Symbol`はencoded textではなくimmutableなbyte値なので、characterやgraphemeではなくbyte位置で分けるoperationが必要になる。
ambientな`substr`やmethod lookupを導入せず、既存の算術operatorと同様に値へ常在するclosed primitiveとして表す。

`/`を分割のquotient、`%`をそのremainderと見ると、二つのoperatorの関係を一つの分割則で定義できる。`%`の後へ`/`を
左結合すればoffsetとlength、`/`の後へ`%`を左結合すればstartとendによるrangeになり、専用の三項slice構文を必要としない。

## 採らなかった案

- `substring(value, start, length)`のようなpredefined function: basic byte operationをambient nameにし、`Symbol`自身の
  primitive operationと利用者定義functionの境界が曖昧になる。
- 専用のslice構文: 同じrangeを既存operatorの合成で表せる一方、新しいprecedenceとparser ruleが必要になる。
- `/`と`%`へ異なるprecedenceを与える: numeric operationとの共通の読み方を崩し、二つのrange表現で括弧の規則が異なる。
