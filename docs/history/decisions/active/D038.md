# D038. lambda parameter型を期待関数型から決める

- Status: Accepted
- Date: 2026-09-09
- Scope: mal v0.5 source language

## 決定

lambda parameterは名前だけを宣言し、型annotationを持たない。lambdaは周辺から与えられる期待関数型に対して
検査し、期待型がなければ拒否する。

0 parameterは`Unit`、1 parameterは期待parameter型全体、複数parameterは期待parameter productの各要素へ
source orderで対応させる。要素数は一致しなければならない。lambda bodyは期待result型に対して検査するため、
高階関数のinner lambdaにも型を再帰的に伝播できる。

## 理由

関数型のauthorityを周辺の型annotationまたはapplicationの既知のparameter型へ一元化し、同じparameter型を
bindingとlambdaへ重ねて書く必要をなくす。lambda単独から型を合成せず、operandや利用箇所から逆向きに推論する
一般的な型推論は導入しない。

named lambdaは完全な関数型をbindingへ明示する。既知のhigher-order functionへ直接渡すlambdaと、annotated
lambdaのresultとして返すinner lambdaは、既存の期待型伝播だけで検査できる。自己再帰は従来どおり、型annotationと
直接のlambda RHSを持つ単一名bindingだけに認める。
