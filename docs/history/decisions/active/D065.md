# D065. 自己再帰で保持されるparameter fieldを物理frameから除く

- Status: Accepted
- Date: 2026-09-19
- Scope: execution plan、reference LLVM backend

## 問題

non-tail自己再帰ではresume stateのlive-inをcontrol frameへ保存する。再帰の全edgeが同じparameter fieldを同じbindingから渡す場合も、
callee entryは同値を同じslotへ書き、frameはその値を深さごとに複製していた。029では不変なtreeとqueryがrecursive frameを広げていた。

semantic livenessからfieldを削るとresumeの入力契約を偽る。LLVMだけで同値性を推測すると、application targetとrecursive edgeを所有する
execution authorityを迂回する。

## 決定

`execution/optimization/frame_pass_through`は単一functionのrecursive regionだけを対象とする。すべての自己再帰edgeについて、parameter
destructuringの同じfieldへ同じbindingが渡される場合、そのbindingをpass-through候補にする。targetが曖昧なedgeとmutual recursionは
対象外にする。

semantic frame fieldとownership planは維持する。LLVM backendは候補がunmanagedまたはownership上borrowの場合だけphysical layout、
store、resume loadから除く。callee entry後も同じslotに同値が残るため、resumeはslotをそのまま利用する。baselineは候補集合を空にする。

## 帰結

- frameのlive-in、result、effect order、owner responsibilityは変わらない。
- 変化するparameter fieldとborrowでないmanaged fieldは従来どおり保存する。
- 029のmaximum inputは172.67 msから160.07 msへ短縮し、textは7,984 bytesから7,520 bytesへ縮小した。
- 032の自然な再帰はframeが96 bytesから40 bytesへ縮小したが、65.66 msから64.84 msの改善に留まった。
