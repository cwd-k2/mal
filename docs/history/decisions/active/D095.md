# D095. 選択したimplementationの`Storable` requirementをspecializationで検査する

- Status: Accepted
- Date: 2026-10-02
- Scope: operation familyのimplementation選択
- Refines: D086、D094

## 問題

generic本体は、自分のsignatureから導けるrequirementを仮定でき、callerがそれを満たすことを検査する。implementationの
signatureはfamily signatureへkeyを代入した型であり、family signatureより多くのrequirementを持ち得る。
`extend<W, A, B> :: (W<A>, W<A> -> B) -> W<B>`のfamily signatureでは、open application `W<B>`の中に`Storable(B)`を要求できない。
一方、`opaque Focus<A> :: (Buffer<A>, USize)`をkeyとするimplementationのsignatureは`Focus<B>`を含み、本体は`Storable(B)`を
仮定して`make<B>`を呼べる。callerはfamilyのrequirementしか検査されないため、`B`がBufferを含む型でも選択が通り、
Buffer elementを`Storable`に限る規則が破れていた。

## 決定

implementationは、keyを代入したsignatureから得る`Storable` requirementを保持する。specializationがimplementationを選択した時点で
pattern binderへのconcrete substitutionを適用して検査し、満たさない場合は選択したreferenceを示すcompile-time errorにする。
規則は[operation family](../../../spec/operation-families.md#selection)に置く。

## 理由

- [D093](D093.md)のkind requirementと同じく、本体を一度だけ検査する構造を保ったまま、型argumentがconcreteになった時点で条件を
  確かめられる。
- implementation宣言時にfamilyより多いrequirementを拒否すると、Bufferを表現に持つ型をkeyとするimplementationを書けない。
  `pure`や`extend`をBuffer上のcontainerについて実装する用途を理由なく閉ざす。
- family signatureへ`F<A>`の中のrequirementを加えると、`Id<A> :: A`のようにelementを保持しないconstructorでも`Storable(A)`を
  要求し、正しいprogramを拒否する。
