# D080. Engram carrier lifecycleをLLVM backendの共通境界へ集約する

- Status: Accepted
- Date: 2026-09-28
- Scope: reference LLVM backend

## 問題

managed valueのresponsibilityは`execution/ownership`が決めていたが、LLVM backendではpattern destination、parameter handoff、
frame resume、Buffer operation、Symbol move、dead-slot cleanupがcarrierのload、store、zeroing、releaseを個別に組み立てていた。
型別retain/releaseが共通でも、carrierの初期化、移動、上書き、破棄を迂回する経路が残ると、二重releaseやlive valueの上書きを
新しいEngram leafごとに再発させ得る。

## 決定

responsibility policyは引き続き`execution/ownership`が所有し、LLVMの`body/value`へ次のbackend-local境界を集約する。

- managed typeの再帰的なshareとdrop
- slotからのload、vacant carrierへのinitialize、Consume後のvacate
- live managed placeのreplace
- pattern destinationとdead-slot cleanup

pattern、parameter handoff、frame resume、Buffer `put`、Symbol moveはこの境界を使用し、個別にmanaged carrierをstoreまたはzeroにしない。
独立したlifecycle plan、runtime type descriptor、共通owner header、source-level retain、release、manual dropは導入しない。

## 理由

[D055](D055.md)のowner successorとresponsibilityをtarget-independentなpolicy authorityに保ったまま、物理的なcarrier状態遷移を
一箇所で実装できる。reference countingは観測可能なsource semanticsではなく、別の回収方式へ置換できる実装詳細のまま残る。

## 後続

Buffer element callbackとclosure environment destructorが同じ型別loweringを共有する範囲、追加のbackend-local validation、
新しいEngram leafのextension境界は
[Engram lifecycle loweringの共通基盤](../../../proposals/engram-lifecycle-foundation.md)で継続して評価する。
