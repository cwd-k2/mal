# D090. blockで始まるbodyも一つのexpressionとして続く

- Status: Accepted
- Date: 2026-09-29
- Scope: grammar、parser

## 問題

grammarはlambda、result block、`if`のbranch、`when`のbodyを一つの`expression`と定め、tree-sitter grammarもそのとおりに
解析していた。compilerのparserは`{`で始まるbodyをその`}`で打ち切ったため、`(x) -> { x } + 1`を`((x) -> { x }) + 1`と読み、
`if (c) then { a }[k] else b`を構文errorにし、`if (c) then { a } else { b }.f()`の`.f()`を`if`全体へ適用していた。

## 決定

bodyは常に一つのexpressionとして解析する。blockで始まるbodyの後にsuffixやbinary operatorが続けば、blockはそのexpressionの
左端のoperandになる。bodyがblockだけなら、従来どおりそのblockのbody itemをbodyとする。規則は
[字句と文法](../../../spec/grammar.md#expression-form)に置く。

## 理由

- 仕様とeditor grammarがすでにこの読みを定めており、compilerだけが別の言語を受理していた。
- 規則を「bodyはexpression」の一つに保ち、`{`で始まるかどうかで後続tokenの帰属を変えない。
- repository内でこの差に依存していたのは、lambdaへ直接suffixを適用していた二つのdriver testだけで、括弧を加えて
  同じ意味にした。
