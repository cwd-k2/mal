# D092. phantom parameterの型argumentをconstructorでない場合に推論する

- Status: Accepted
- Date: 2026-09-30
- Scope: generic value referenceの型argument推論
- Refines: D086

## 問題

opaque typeのphantom parameterは表現からkindが決まらず、[kind推論](../../../spec/type-constructors.md)によりkind多相へ
generalizeされる。そのparameterにしか現れないgeneric bindingのparameterも同じくkind多相になり、kind `Type`のargumentだけを
推論する規則では推論されなかった。`Deque<UInt64>`の値を渡しても`dequeLength<UInt64>(deque)`のように型argumentを書く
必要があり、型付きhandleのようにphantomなtagで値を区別するopaque typeで、操作ごとに明示が要った。

## 決定

kind未制約のparameterも、unificationでparameter自身に対応したtypeがconstructor kindでなければ推論する。そのtypeはvalue型か、
外側のgeneric bindingが受け取ったkind未制約のparameterである。推論したargumentは明示argumentと同じkind検査を受ける。
constructor kindのargumentは従来どおり明示prefixとしてだけ与える。規則は[parametric polymorphism](../../../spec/generics.md)に置く。

## 理由

- parameter自身への一次の対応だけを使うため、[D086](D086.md)が避けたhigher-order unificationを導入しない。
- constructorを推論しないので、「constructorは明示し、それ以外を推論する」という利用者向けの規則は変わらない。phantom位置に
  現れたconstructorも推論する形は、同じconstructorでも出現形で推論の可否が変わるため採らない。この形は後から受理範囲を
  広げるだけで追加できる。
- 対象のparameterは従来必ずerrorになったため、既存programの推論結果とspecialization keyは変わらない。
- 同じkind変数を共有するparameterがあるため、推論したargumentにもkind検査が必要である。
