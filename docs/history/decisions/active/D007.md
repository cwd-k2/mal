# D007. lexical captureを推論する

- Status: Accepted; lambda parameter spelling superseded by D038
- Date: 2026-09-07
- Scope: mal v0.5
- Refines: D003

## 決定

lambdaはbodyから参照する外側local bindingをby-valueで暗黙にcaptureする。

```mal
makeAdder := \(x :: Int32) {
    \(y :: Int32) { x + y };
};
```

name resolutionはbinding identityに基づくfree-variable集合をlambdaごとに求める。nested lambdaだけがさらに外側の値を
参照する場合、各中間lambdaは内側closureを構築するためにその値を自動的に転送する。parameter、同じlambdaのlocal、
self referenceはcaptureせず、top-levelとpredefined valueは従来どおり直接参照する。

capture集合はlexical semanticsで確定し、compilerが選ぶDirect、stack、heapなどのenvironment配置によって変えない。
集合の内部順序はsourceから観測できない。

## 理由

captureのlifetimeと回収はmanaged Engram ownershipが担い、environmentの配置はsourceから観測できない。escape解析により
environment allocationを除去またはstack化できるため、bodyに現れるlexical依存を別のsource記述へ重複させず、
通常のlexical closureとして扱う。

意図しないresource保持を型として防ぐ必要がある場合は、resourceまたはcapabilityのlifetime規則として設計する。
`Ptr`のreferentとexternal opaque resourceは引き続きhost contractに属し、暗黙captureによって新しいlifetime保証を得ない。
