# D100. C call capabilityとruntime mechanismを分離する

- Status: Accepted
- Date: 2026-10-19
- Scope: C ABI、reference compiler、runtime、documentation
- Refines: D098、D099

## 決定

C extension ABIを`0x000c00`へ上げ、publicな`mal_call_t`をincompleteな`struct MalContext`を指すためのopaqueな型名とする。
hostは`mal_call_t`のsize、alignment、field layoutに依存せず、値を構築またはcopyしない。extern bodyが受け取ったpointerは同期的な
Call APIにだけ使用し、body完了後に保持しない。

具体的な`MalContext`とcontrol arenaのlayoutはgenerated shimとruntimeが共有するprivate runtime headerが所有する。genericなownerと
byte ownerのretain、release、uniqueness operationもprivate runtime mechanismとする。public headerのgenerated lifecycle glueは、
SymbolまたはBufferのaddressable carrierを受ける型別entry pointを使用し、owner representationを直接操作しない。旧layoutとgeneric
operationのcompatibility declarationは残さない。

## 理由

extern bodyに必要なのはactive runtimeへの限定されたcapabilityであり、contextを構成するauthorityやcontrol storageのlayoutではない。
concrete layoutをpublic headerに置くと、native stack管理やcontrol storageの変更がhost source contractへ漏れ、generic owner operationを
公開すると任意の内部pointerをlifecycle対象として扱えるように見える。

opaque capabilityとcarrier単位のlifecycle entry pointへ境界を狭めれば、publicなcarrier、extern signature、responsibility規則を維持した
ままruntime mechanismを変更できる。exact-version policyに従い、曖昧なsource compatibilityより誤ったheader/runtimeの組み合わせを
compile時に拒否する。

## 帰結

- host sourceは`sizeof(mal_call_t)`、`_Alignof(mal_call_t)`、field access、stack allocationを行えない。
- generated shimはprivate headerを読み、entry pointで具体的なcontextを構築できる。
- `mal_share`と`mal_drop`はcarrier単位のcallbackを通し、generic owner pointerをpublic APIへ露出しない。
- ABI version、public capabilityの制約、lifecycle contractは[C runtime extension ABI](../../../spec/c-host-abi.md)と
  [C host value API](../../../spec/c-host-api.md)を正とする。
