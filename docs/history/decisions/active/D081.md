# D081. 型引数を局所constraintで推論しoperation familyをexact keyで解決する

- Status: Accepted
- Date: 2026-09-28
- Scope: language, compiler, formatter, and editor tooling

## 問題

generic valueの全利用箇所で型argumentを明示すると、operandや期待resultから一意な情報を重複して記述する。
また、generic collectionが`equal<T>`や`hash<T>`を必要としても、型別operationをcompile-timeに結ぶ仕組みがなく、
operationを引数として全階層へ手渡すか、collection本体を型ごとに書き直す必要があった。

実装候補から型argumentを逆算すると、別fileへのimplementation追加で既存programの推論が変わり、overlapと選択規則が
型検査へ混入する。runtime dictionaryを導入すると、specialization後は単相coreだけを渡す既存境界も広がる。

## 決定

generic value referenceごとの局所solverが、declaration signatureと次の周辺情報をalias展開後に構造的にunifyして型argumentを決める。

- operandとparameter
- application resultと期待型
- higher-order位置の期待関数型
- parameter型が確定したlambda resultとdirect result binder payload
- 直和continuationのpayload型、および既知の除去結果型

initializerを持たないgeneric value headerはoperation familyを宣言し、同じfamily identityへclosed canonical type argumentと
initializerを置いたheaderをexact implementationとする。generic本体のsymbolic family referenceは`OperationRequirement`として保存し、
specializationでconcreteになったexact keyを一意なimplementationへ解決する。implementation集合は型推論のconstraintに使わない。
specialization後はfamily、requirement、型argument、dictionary、type descriptorをcoreへ残さない。

## 理由

推論をcall siteのsignatureと周辺型だけへ閉じると、implementation集合から独立した安定な結果になる。exact keyだけの初期profileは
coherenceとterminationを有限なprogram-wide重複検査で扱え、既存の単相backendを変更せずにgeneric algorithmを再利用できる。

## 非目標と後続

generic implementation pattern、specificity、higher-kinded constructor、lawful interface、runtime dispatchは採択しない。
これらの利用例と未決事項は
[型引数推論と型別operation family](../../../proposals/inferred-operation-families.md)で管理する。現在の規則は
[parametric polymorphism](../../../spec/generics.md)と[operation family](../../../spec/operation-families.md)を正とする。
