# D077. predefined名をtop-levelで再宣言しない

- Status: Accepted
- Date: 2026-09-25
- Scope: language (program structure) and reference compiler

## 問題

resolverはtop-level bindingがpredefinedの`new`、`get`、`put`だけを再宣言することを認め、`make`、`fill`、`copy`、`into`、`from`、
`false`、`true`、predefined型は拒否していた。この例外は仕様になく、再宣言した名前をrequireした別fileではpredefined名と衝突して
importできなかった。例外に依存するprogramはchecker testの一つだけだった。

## 決定

predefined型とpredefined valueの名前は、各fileのtop-levelで型、binding、extern declarationとして再宣言できない。local scopeでは
通常のshadowing規則によりpredefined valueをshadowできる。規則は[プログラム構造](../../../spec/programs.md#program-と-source-file)に置く。

## 理由

- `Bool`、`false`、`true`に既にあった規則を全predefined名へ揃えると、例外の一覧を仕様にもresolverにも持たずに済む。
- top-level名はrequire元へ導入されるため、predefined名と同じtop-level名はfileを跨いで必ず衝突する。file内でだけ許すと、
  同じ宣言がfileの位置によって有効にも無効にもなる。
- Buffer operationはpredefined identityで認識するので、local scopeのshadowingは既存の意味のまま残る。
