# D084. source-defined opaque typeのrepresentation authorityを宣言元fileへ限定する

- Status: Accepted
- Date: 2026-09-28
- Scope: language, compiler, formatter, and editor tooling

## 問題

transparent aliasではcontainer invariantを利用側から隠せず、external opaque typeではmal自身がrepresentationを構築、分解できない。
専用の`pack`と`open`を加えると、既存のproduct、sum、functionの構文と同じ変換を別の表面構文で重複して表す。

## 決定

`opaque Name<A> :: Representation<A>;`を導入する。型はdeclaration identityと型argumentをcanonical identityに残す。
宣言元fileだけは通常の型検査でrepresentationを双方向にviewでき、既存の構築、pattern、elimination、application構文を使う。
別fileはopaque identityの値を受け渡せるが、representationを観察できない。specialization後はrepresentationへzero-costで消去する。

## 理由

abstraction authorityをsource fileへ置けば、public operationがinvariantを所有しつつ、runtime wrapperや新しいcontrol formを増やさずに済む。
canonical keyへidentityを残すことで、同じrepresentationの別型やoperation implementationを混同しない。

現在の規則は[file-local opaque type](../../../spec/types.md#file-local-opaque-type)を正とする。
