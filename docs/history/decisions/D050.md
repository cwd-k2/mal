# D050: bodyをexpressionに統一しbinder境界へ`->`を置く

Status: Superseded by D051

## 決定

lambdaはparameter groupとoptionalなreturn binder groupの後に`->`を置き、その右辺に一つのexpressionを取る。
direct result blockもresult binder groupとbody expressionの間に`->`を置く。`if`の両branchと`when`のbodyも
一つのexpressionとし、複数のbody itemや局所bindingが必要な位置ではblock expressionを使う。

```mal
add :: (Int32, Int32) -> Int32 := (a, b) -> a + b;

choose :: Bool -> [Int32, Symbol] :=
    (condition)[integer, symbol] ->
        if (condition) then integer(42) else symbol("disabled");
```

従来の`(parameter) { body }`、`[result] { body }`は受理しない。braceを伴う形はそれぞれ
`(parameter) -> { body }`、`[result] -> { body }`と書く。型位置のfunction arrowとterm位置のbinder arrowは
同じ`->` tokenを使う。

## 理由

braceの有無ではなく`->`によってbinder導入を識別すると、parameter group、return binder group、result binder groupと
bodyの境界がbodyを読む前に確定する。bodyをexpressionに統一することで、単一計算のためだけのbraceを不要にしながら、
複数stepとlexical scopeには既存のblock expressionをそのまま使える。型とtermは構文上の位置が異なるため、同じarrowを
使って写像としての対応を示してもsyntax admissionは曖昧にならない。

## 置き換える判断

[D038](D038.md)のlambda parameter source spellingと[D049](D049.md)のdirect result block source spellingを置き換える。
lambdaの期待型検査、direct blockとdirect result blockの意味、return binder、completion、sum構築の規則は変更しない。
現在の規範は[式とbinding](../../spec/expressions.md)、[明示的returnとcompletion](../../spec/control.md)、
[字句と文法](../../spec/grammar.md)を正とする。
