# D034. C adapterへmanaged carrierのclone・move・drop規約を提供する

- Status: Superseded by D040
- Date: 2026-09-07
- Scope: v0.5 reference C host ABI
- Refines: D033

## 決定

C adapter内のmanaged carrierを概念上borrowed、owned、movedの三状態に分ける。Cの型systemによる静的な区別は
導入せず、generated headerが型ごとの`clone`、`take`、`drop` operationと、それらを選ぶ`MAL_CLONE`、
`MAL_MOVE`、`MAL_DROP` macroを提供する。

`clone`はborrowed valueからownership shareを一つ作る。`take`はowned lvalueのshareをresultへ移し、元を
zero-initializeしたmoved状態にする。`drop`はowned lvalueのshareを解放してmoved状態にする。moved値への
`drop`はno-opである。productとsumではmanaged fieldへ再帰適用し、Extern capabilityは複製または解放しない。

aggregate constructorはmanaged argumentのownership shareをresultへconsumeする。accessorが返すmanaged fieldは
borrowである。extern resultはowned valueをmalへconsume-transferする。通常のC assignmentはownership shareを
増やさない。

## 理由

ABI carrierをby-valueで渡すCだけでは、borrowとownership shareの違いを表現できない。規約だけではparameterを
そのまま返す、同じdescriptorを複数fieldへ入れる、failure pathでtemporaryを忘れる誤用が起きやすい。一方、別の
carrier型やC compiler extensionを要求するとadapterと既存libraryの接続面積が増える。

型ごとの小さなoperationなら、値表現を変えず、引数を一度だけ評価し、portable C11の範囲でmove元とdrop済み値を
emptyにできる。macroは既存の`MAL_OPERATION` naming conventionへ展開するだけであり、ownership mechanismを
preprocessorへ実装しない。

## 帰結

- C compilerはborrowed、owned、movedの誤用を完全には拒否しない。adapterは引き続きtrusted computing baseである。
- managed valueを含むunnamed structural aggregateにもrepresentation owner名で同じoperationを生成する。
- `Ptr`とexternal opaque valueのresource ownershipはoperation固有contractのままであり、`drop`はclose/freeしない。
- ABI helper追加はv0.5 development profile内の変更とし、`MAL_C_ABI_VERSION`は変更しない。
