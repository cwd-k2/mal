# D068. external memoryをscoped Region APIへ整理する

- Status: Accepted
- Date: 2026-09-19
- Scope: language、editor tooling、reference compiler

## 問題

`Cursor`、placement、load/store operator、Region projectionが、raw location、有限範囲、ownershipのauthorityを複数の表現へ
分散していた。Packed構築も初期capacityの有無だけで`pack`と`bulk`に分かれ、external storageからのadmissionと同じ名前を共有していた。
構文だけで定義されるoperationはeditor上で宣言へ移動できず、利用者が型と契約を確認しにくかった。

## 決定

raw capabilityは`Address`、有限external storageは`view<A>(Address, USize, USize, Region<A> -> R) -> R`がcallback中だけ導入する
`Region<A>`へ分ける。`Cursor`、placement、alignment、RegionからAddressへのprojection、load/store operatorを設けない。
Region accessは`get`、`put`、Packedの連続書き込みは`set`とする。external storageのadmissionは
`pack<A>(Address, USize, USize)`、Packed構築は`make<A>(capacity, callback)`、編集は`edit`とする。

`Region<A>`と`Buffer<A>`を再帰的に含むparameterはscoped authorityとして扱い、result、nested lambda capture、通常のgeneric type
argumentを通じたescapeをcompile-timeで拒否する。Packed同士の`+`を連結とし、prefix `/`とremainder `%`は副作用を連想させない
operatorのまま保つ。zero-stride elementはAddressを観測せずlogical countだけを扱う。

predefined type、intrinsic、receiver-first operationのsignatureと説明はcompiler内の一つのmetadata authorityからsemantic indexへ公開し、
hoverとcompletionで利用できるようにする。規範的な型、評価順、preconditionは
[external memory](../../spec/memory.md)と[`Region`と`Packed`](../../spec/packed.md)を正とする。

## 帰結

- raw addressを渡されたcodeとtyped finite accessを委譲されたcodeのauthorityが区別される。
- `make(0usize, callback)`を含む一つの構築primitiveで初期capacityを明示できる。
- 旧構文や旧名称を互換経路として保持せず、grammarから除去する。
- lexicalな保守的規則を選び、escape analysisとscope polymorphismは導入しない。
