# D072. 直和除去のlambda literal continuationをbranchとして扱う

- Status: Accepted
- Date: 2026-09-25
- Scope: language (sum elimination, result binder)

## 問題

`if`と`when`のbranchは囲むlambda invocationに属するので外側のresult binderを適用して早期脱出できる。一方、payloadを受ける直和除去の
continuationはlambdaとして書くため外側のbinderを参照できず、成功側の残りをcontinuationの中へ入れ子にするしかなかった。
[D049](D049.md)は直和除去のcontinuation位置へbare blockを置く案を、外側binderへの到達などを一つの規則で説明できるまで保留していた。

## 決定

二つ以上のcontinuationによる直和除去で、continuationの位置に直接置いた次の二つを扱う。括弧は意味を持たないので剥がして判定する。

- lambda literal `(pattern) -> body`は、囲むinvocationに属するbranchである。`pattern`は第`i`項のpayloadを束縛し、bodyは外側のresult binderを
  参照して適用できる。completionは`if`と同じ`join`で畳み込み、すべてが`Abrupt`なら全体が`Abrupt`である。
- result binder名`k`は、第`i`項のpayloadを`k`へ適用するcontinuationと同じで、parameter型が第`i`項と一致しなければならない。

変数へ束縛したfunctionや`f(x)`のような他の式、bodyの中のlambdaは従来どおりfunction値で、binderを参照できない。
規則は[直和の除去](../../spec/expressions.md#直和の除去)と[result boundaryとcompletion](../../spec/control.md)に置き、
理由は[lambdaの中断とredex](../../design/value-interpretation-and-control.md#lambdaの中断とredex)に置く。

## 理由

result binderをnested lambdaから参照できないのは、値としてのlambdaが持つ中断がbinderの生存範囲を越え得るからである。その場で一度だけ
applicationされるlambda literalはbeta redexで中断を持たず、`:=`と同じくbodyが囲むinvocationに属する。sum continuationのlambda literalは
case分岐であり、束縛名の選択も動的意味も変えず、受理範囲だけが広がる。closureが作られないので、外側の変数をcaptureするcontinuationの
environment allocationと別functionへの呼出しも生じない。

D049はlambdaの即時applicationへの展開がstatic semanticsを変えることを理由にdirect blockを別構文とした。この決定はその前提
「その場でapplicationされるlambda literalは中断を持つlambda値と同じ境界」を、直和除去のcontinuationについて改める。direct blockを
lambdaの省略形としない判断は維持する。

## 帰結

- 単一continuationの`x[(n) -> body]`とcallee位置のlambda literalは、同じredexだが未適用で、[提案](../../proposals/immediate-lambda-redex.md)に残す。
- syntaxは変わらないので、formatterとTree-sitterは変わらない。
- core loweringはcontinuationをpattern付きcase armとして`if`のbranchと同じjoinへ接続し、ANF以降は変わらない。
