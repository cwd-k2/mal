# D070. 実行環境をLLVM backendとC hostに固定する

- Status: Accepted
- Date: 2026-09-24
- Scope: language specification and `malc`

## 問題

仕様と設計文書は「C host profile」「reference compiler」「別backendを妨げない」という語で、差し替え可能な実行環境の層を仮定していた。
実際に存在する環境はLLVM backendとC hostだけであり、`from<T>`、`buffer.into`、extern C ABI、canonical layoutはこの環境のtarget ABIと
data layoutに結び付いている。仮定した層は、条件付きの言い回しと、同じ事実を複数の文書へ置く重複を生んでいた。

## 決定

実行環境を`malc`のLLVM backendとC hostだけに固定し、他のbackendやhostへの対応規則を仕様に含めない。`from<T>`と`buffer.into`を
含むC host固有のoperationは通常のpredefined operationとして仕様に書く。「profile」と「reference」の語は、仮定した層を表す用法をやめる。
`--optimization`の`production`と`baseline`は最適化の選択でありprofileではない。

機能を加える判定基準から「別backendを不必要に妨げないか」を外す。ただし言語semanticsはLLVM、C、host Rustの偶発的な挙動へ依存させない。
評価順、integer overflow、trap、floating-point変換は、仕様が明示する規則を`malc`の該当stageが保証する。

## 帰結

- 実行環境と`malc`の対応環境は[言語の範囲](../../spec/scope.md#実行環境)と[`malc`利用contract](../../development/compiler-usage.md)に置く。
- 他のbackendまたはhostを加える場合は、新しい決定で仕様全体の前提から見直す。
- 実装の責務境界を記す文書は`docs/implementation/`に置く。
