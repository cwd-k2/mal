# D044. editor queryをcurrent syntaxと完全なsemantic analysisに分離する

- Status: Accepted
- Date: 2026-09-13
- Scope: compiler editor API、language server

## 決定

compilerの厳格な`parse -> resolve -> check` pipelineとは別に、current sourceのtokenだけから`SyntaxDocument`を構成する。
完全なanalysisに成功したversionでは従来の`SemanticDocument`を使い、失敗したversionではsemantic tokenと
receiver-first completionを`SyntaxDocument`から提供する。

syntax fallbackはtoken分類、top-level function declaration、完全な`require` declarationだけを扱う。
型、local identity、参照先を推測せず、以前のdocument versionのspanやsemantic indexを再利用しない。require pathは
抽出した宣言列を既存driverへ渡して解決し、language serverに別のpath resolutionを実装しない。

## 理由

編集中の一つの不完全なexpressionによってfile全体のsemantic tokenとcompletionを消すと、通常の記述操作が不安定になる。
一方、以前の成功versionをそのまま返すと、挿入や削除後のspan、scope、型がcurrent sourceと一致する保証がない。

[rust-analyzerのsyntax architecture](https://github.com/rust-lang/rust-analyzer/blob/master/docs/book/src/contributing/syntax.md)は、
semantic情報を持たないlosslessかつerror-resilientなsyntax treeを、後段の意味解析と分離している。Malも同じ責務分離を採るが、
現在必要なfallbackはtoken分類とtop-level declarationに限られるため、dependencyと汎用treeを追加せず小さいimmutable indexで表す。
将来partial hoverやnavigationを提供する場合は、同じsyntax layerへparser recovery nodeを追加し、syntax tokenから型やidentityを
推測する範囲を拡大しない。

現在の利用方法とfallback範囲は[editor tooling](../../development/editor-tooling.md)、module責務は
[compiler responsibilities](../../implementation/responsibilities.md)を正とする。
