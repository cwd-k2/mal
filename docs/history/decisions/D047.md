# D047: completion後続のlexical join表現

Status: Accepted (2026-09-13)

## 決定

core loweringは、複数の正常出口から同じlexical continuationへ進むとき、後続expressionを各出口へ複製しない。lambdaが
join bodyを平坦なarenaとして一度だけ所有し、正常出口はjoin identityとargumentを持つ`goto`で参照する。ANFとclosure
conversionはこの関係を保持し、control loweringが既存のinput付きstateと`Jump`へ変換する。

joinはsource languageのname、value、first-class continuationではない。lambda外へescapeせず、型検査済みcompletionの
`Value` pathを共有するためだけに使う。`Abrupt` pathはjoinを経由せずlambda resultへ進むため、extern作用の評価順と回数を
変えない。

## 理由

checked body itemはvectorでも、後続を各branchへ木として配るCPS変換では、平坦なcontrol item列が深いhost再帰になり、二つ以上の
正常出口を持つitem列ではcore AST量が指数的に増え得る。後続をsynthetic lambdaにする案は通常のcore calculusだけで共有できるが、
sourceにないclosure allocationとcallを導入し、長い列をnested lambda ownershipとruntime call chainへ置き換える。

control stageは既にbranch resultをinput付きjoin stateへ集約する。したがって前段は実行機構を重複して実装せず、そのstateを一意に
構成するためのlexical identityだけを保持する。arena ownershipによりjoin数に対するRust `Drop`深度も一定になる。

## 棄却した案

- 後続expressionをbranchごとにcloneする: compile量が実行path数に比例し、平坦なsourceから指数的なtreeを作る。
- synthetic lambdaとcallへ変換する: closure allocation、call planning、native call chainをsourceにない形で追加し、AST所有深度も移すだけになる。
- control item数へ固定上限を置く: CFGでは線形に表せる入力をcompiler実装都合で拒否する。
