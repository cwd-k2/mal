# D045: reference compilerの構文深度上限

Status: Accepted (2026-09-13)

## 決定

reference compilerは再帰的な構文構造を一つのparse中で64 levelまで受理し、超過をparserのstructured diagnosticとして
拒否する。平坦な宣言列、block item列、argument列、aggregate element列、左結合operator列はこの深度へ数えない。

この上限は言語意味論、program実行時のtrap、後段loweringの都合による制約ではない。parserがsource admission時に所有する
implementation resource limitである。

## 理由

括弧、lambda、control form、prefix operator、右結合function型、nested patternはsource自体が再帰的なtreeを指定する。
有限memory上で任意深度を無条件に受理することはできず、全stageを複雑なstackless tree engineへする利益も通常のsourceにはない。
一方、平坦に記述できる列を内部の二分木やlinked structureだけで同じ上限へ巻き込むのは入力構造を正しく表さない。

既存実装で用いるClangも括弧、bracket、braceに既定値256の有限上限を持つ。reference compilerではRust test thread上で
128重のparenthesized expressionが上限検査なしにはstack overflowした実測を踏まえ、複数のrecursive parser functionを通る
現在のframe構成に安全余裕を持たせて64とした。比較対象のClangの値は
[`-fbracket-depth`](https://clang.llvm.org/docs/UsersManual.html#controlling-implementation-limits)で公開されている。

## 棄却した案

- host stack overflowに任せる: diagnosticを返せずcompiler processがabortする。
- source byte数だけを制限する: 小さい深いsourceと大きい平坦なsourceを区別できない。
- 全構文を無制限の明示stackへ移す: memory exhaustionという最終上限は残り、通常入力に対して複雑さだけが増える。
