# D037. memory primitiveを型修飾形で表す

- Status: Accepted
- Date: 2026-09-09
- Scope: mal v0.5 source language

## 決定

canonical memory representationを持つnumeric scalarと`Ptr`に、型で修飾した`size`、`load`、`store`を
定める。外部regionと`Symbol`のraw bytesをcopyするoperationは`Symbol.read`と`Symbol.write`とする。

```mal
UInt64.size
UInt64.load(pointer)
UInt64.store(pointer, value)
Symbol.read(pointer, length)
Symbol.write(pointer, value)
```

`.`はlexerで単独のtokenとして認める。source grammarが認めるのは`TYPE_IDENT.VALUE_IDENT`の形を持つ
type-qualified primitiveだけである。module、namespaceのqualified name、field access、method、user-defined
associated itemは導入しない。member集合はmemory仕様が完全に列挙する。

transparent aliasは展開後のcanonical typeが持つprimitiveを同じ形で使える。`load`、`store`、`read`、
`write`はfirst-class function、`size`は`UInt64`のtarget constantである。

従来の`@T`、`loadT`、`storeT`は削除し、開発中のsource languageで後方互換を維持しない。D022、D024、
D027、D031がmemory operationに定めた意味は変更せず、source spellingとname lookupだけをこの決定が置き換える。

## 理由

`@T`はexpression内でtypeをoperandに取る専用operatorであり、load/storeは型名を連結したambient nameと
してpredefined scopeを広げていた。型を起点にした固定の三operationへまとめることで、型とcanonical
representationの対応、利用可否、first-class functionとしての型を一つの表から決められる。

`Symbol`のoperationはcanonical object representationのload/storeではない。`read`はraw bytesをcopyして新しい
mal-controlled valueを構築し、`write`はdescriptorやownershipを渡さずraw bytesだけをcopyする。この違いを
operation nameに保ち、`Symbol.size`、`Symbol.load`、`Symbol.store`は定めない。

numeric conversionの`T(value)`とsum injectionの`T[index](value)`は、型を指定して値を構築する既存の
syntaxとして維持する。source型によって複数のsignatureを持つnumeric conversionを、一つのfirst-class
associated functionに見せない。

## 採らない案

- `load.UInt64`と`store.UInt64`: operation familyの少なさは強調できるが、`size.UInt64`は型が持つstorage幅を
  読む順序として不自然で、operation名をnamespaceのように扱う。
- `UInt64[load]`: sum injectionの`T[index](value)`と類似し、variant selection、indexing、generic specializationを
  暗示する。
- 一般的なassociated itemやmodule: 現在必要な固定のmemory mechanismを越え、declaration、visibility、lookupの
  仕様面積を増やす。
