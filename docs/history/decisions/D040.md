# D040. C host interfaceをtyped valueとterminal returnに限定する

- Status: Accepted
- Date: 2026-09-09
- Scope: reference C host ABI v0.6

## 決定

host bodyは`MAL_DEFINE_<operation>(call, value)`で定義し、source-level parameterを一つのtyped host valueとして受け取る。
resultは型ごとのterminal return helperで完了する。raw compiler carrier、managed ownership primitive、Symbol storage表現は
host interfaceに公開しない。

`Symbol` parameterは必要になった時点でspanとして観測する。host bytesから作るdescriptorはpureであり、terminal returnが
body終了前にmal-owned storageへcopyする。Mal由来のborrowed Symbolを返す場合はterminal returnが必要なshareを作る。

external opaque valueはone-word handleと`to_bits` / `from_bits`、`Ptr`は`void *`として扱う。productとsumは通常のtyped C valueで、
sum resultはvariant-specific returnを使う。不正なBool、sum tag、spanはterminal boundaryでtrapする。

この変更はpublic ABIをv0.6へ上げ、異なるpublic interfaceを同じheaderへ混在させない。

## 理由

hostにraw carrierとownership protocolを同時に見せると、hostがmal内部のrepresentationとlifetime authorityを再実装する必要が
生じる。call capability、typed value、terminal returnだけなら、authority crossingは一箇所で検査・copy・shareできる。

source productをbody側でもflattenする必要はない。compiler-facing calling conventionはgenerated wrapperが吸収でき、host authorは
source typeの構造だけを扱える。Symbolの遅延観測により、転送または無視する値を連続化する不要なallocationも避けられる。

## 採らない案

- raw wrapperをhostが直接定義する: compiler representationをpublic contractにし、source typeとの対応をadapterごとに重複させる。
- managed clone/move/dropを公開する: linearityをC authorへ委ね、use-after-moveやshare漏れをinterfaceで防げない。
- host bytesをcall終了後もborrowする: malがlifetime authorityを持てず、Engramの不変性を保証できない。
- eagerに全Symbol parameterをmaterializeする: 観測しないoperationにもallocationとfailure pointを追加する。

この判断は[D034](D034.md)のpublic managed transfer helperと[D036](D036.md)のpublic Symbol builderを置き換える。
現在の規範は[C host ABI](../../spec/c-host-abi.md)を正とする。
