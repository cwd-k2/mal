# D032. file requirementは名前導入とC build inputだけを持つ

- Status: Accepted
- Date: 2026-09-06
- Scope: mal v0.5 and reference compiler

## 決定

programはroot `.mal` fileと、各file先頭の`require "relative-path";`から到達するfileで構成する。`.mal` requirementは
対象file自身のpublic top-level declarationを修飾なしで宣言元fileへ導入し、require先が導入した名前を再公開しない。
先頭が`_`のtop-level type/value名はfile-privateとする。fileはnamespace名を持たず、alias、選択的import、qualified name、
package探索、remote dependencyを提供しない。

require graphはcanonical pathでfileを同一化し、cycleを拒否する。各file内のsource orderは維持し、dependencyの名前は
宣言元fileのtop-level itemより前から見える。private declarationのidentityはfileごとに区別する。

reference C backendでは`.c` requirementを名前のない推移的build inputとして扱う。C sourceはprogram全体のgenerated headerに
対してcompileする。object、archive、shared object、追加compiler optionをsource syntaxから指定する機能は持たない。

## 理由

目的は責務に応じたsource分割とhost adapterの同梱であり、独立したmodule objectやpackage distributionではない。
file scopeとvisibilityだけなら既存のtop-level binding、transparent alias、extern boundaryを保ったまま分割できる。

public-by-defaultとleading `_`によりexport listを不要にする。require先のimportを再公開しないことで、各fileの直接dependencyを
sourceから読める。C adapterを同じgraphへ置くことでCLIのlinker inputを通常のprogram構成から除き、mal APIとhost contractを
隣接して保守できる。
