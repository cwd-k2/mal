# D066. recursive regionのcontrol topをlocal SSAへ置く

- Status: Accepted
- Date: 2026-09-19
- Scope: reference LLVM backend

## 問題

non-tail recursive regionはgrowable control storageのoffsetをtopとして使う。従来はroot bridgeが作る一つのtop pointerを各Mal functionへ
渡し、frameのpushとpopごとにそのmemoryを更新していた。region内遷移はLLVM basic block間のbranchであるにもかかわらず、pointerが
native call境界にも渡るため、LLVMはhot loopのtopをSSA valueへ昇格できなかった。

native recursionへ戻すとMal call depthをnative stack depthへ変換し、bounded native stackを失う。C runtimeへprogram固有のtop更新を
移すと、typed frameとstate transitionをLLVMが所有する境界も崩れる。

## 決定

`backend/llvm/optimization/control_top`はcontrol frameを持つrecursive regionのfunctionを選ぶ。選択されたLLVM functionはinvocation
開始時のarena topをlocal slotへ写し、region内のpushとpopはそのslotだけを更新する。local slotのaddressはfunction外へ渡さず、LLVMの
SSA promotionに委ねる。

別のMal functionをnative callするときはlocal topを共有topへ同期する。calleeはその位置をbaseとして使用し、returnまでに同じ位置へ
戻す。region invocationがterminal returnするときもbaseを共有topへ戻す。control byte storage、capacity、growth、frame layout、semantic
live-in、owner responsibilityは変更しない。baselineは従来の共有topだけを使う。

## 帰結

- non-tail recursionは引き続きgrowable storageを使い、native stack使用量はMal call depthに比例しない。
- nested recursive regionとindirect native targetは同期済みtopから開始する。
- 032の自然な再帰は65.09 msから59.64 msへ短縮し、Callgrind instructionは1,510,740,155から1,390,884,286へ減った。
- 029は160.30 msから150.40 msへ短縮した。
