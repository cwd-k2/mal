# D060. editのPacked accessを最初の変更時にlazy preparationする

- Status: Accepted
- Date: 2026-09-19
- Scope: reference LLVM backendとchecked-in C runtime

## 問題

自然な`Packed`利用では、immutableな値を`pack`で構築し、`edit` callbackで変更し、freeze後の値を走査する。callbackが`get`と
`put`をrecursive helperへ渡すと、同じbuilder由来のcapabilityでもcall targetは`Put`と`PutUnique`を含むdispatchになり得る。
通常loweringでは各要素についてindirect callを行い、editの`Put`は毎回copy-on-write判定を含むruntime helperへ入っていた。

callback開始時にbuilderをeditable化すればdata pointerを固定できるが、実際には`put`しないcallbackでもsourceをcopyし得る。
これは仕様が定める最初の変更時のcopy-on-writeより強く、不要なallocationとallocation failureを追加するため採用できない。

## 決定

D059のLLVM techniqueを、homogeneousな`Get`、`Put`、`PutUnique` target集合のdirect accessまで拡張する。non-compact capabilityの
environment tagはbuilderとして使う直前に除去する。

editの`Put`はapplicationが実行された時点でだけruntimeの`prepare_edit`を呼ぶ。runtimeはeditable flagの判定をinlineし、既に
editableならactive dataを直ちに返す。最初の変更に必要なcopy-on-writeとstorage再利用は独立した`noinline` slow pathが所有する。
LLVMは返されたactive dataへ値を書き、`Put` applicationがなければpreparationを一度も行わない。

dataを移動し得るapplicationが後続するdirect accessでは、builder内のdata slotからactive dataを毎回読む。後続の`New`、
`NewUnique`、edit `Put`へ到達しない場合だけ、D059と同じinvariant scopeをdata slotへ開始する。候補が`Put`と`PutUnique`を混在しても、
element型が同じなら`prepare_edit`を行う。unique builderは既にeditableなので、この操作は値を変えない。

## Authorityからの導出

仕様はsourceとresultのimmutableな独立性、先行operationの可視性、最初の変更時のcopy-on-write、必要なallocationのfailureを所有する。
runtimeはeditable flag、copy、storage再利用、active dataを所有する。execution planはapplication targetと到達可能なcontrolを所有する。

したがって、実際の`Put`までcopyを遅延し、runtime mechanismでeditable化した後に同じelement storeを行うことはobservable operationを
変えない。application targetからdirect accessとdata slotのinvariant可否を選ぶことはLLVM backendのauthorityに属する。
callback開始時のeager preparationは、この導出を満たさないためdecision集合に含めない。

## 帰結

- no-op editはsource ownerを共有でき、不要なallocation failureを追加しない。
- editの最初の`Put`だけがcopy-on-write slow pathへ入り、以後の`Put`はinline flag判定とdirect storeになる。
- growthまたは最初のedit変更を跨ぎ得る`Get`はdata slotを再読込し、invariantを宣言しない。
- ordinary functionを含むtarget集合とelement型が異なるtarget集合は通常callへ残す。
- baselineは従来のcapability callとruntime `Put`だけで同じprogramを実行する。
