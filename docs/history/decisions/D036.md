# D036. `Symbol` admissionをruntime-owned builderへ置き換える

- Status: Implemented
- Date: 2026-09-07
- Scope: reference C host ABI

## 決定

hostが返す`Symbol`のadmission APIを、完成済みの外部bytesをcopyするhelperから、reference runtimeが確保した構築中bufferへ
trusted adapterが書き込み、完成時にimmutable `Symbol`としてpublishするbuilderへ置き換える。development中のABIについて
旧copy helperとの後方互換は維持せず、repository内adapterとgenerated headerを同時に移行する。

generated headerは次の形のcarrierとoperationを公開する。正確なC declarationは実装時のheader testで固定する。

```c
typedef struct {
    void *state;
} MalSymbolAdmission;

MalSymbolAdmission mal_SymbolAdmission_begin(
    MalContext *context,
    uint64_t minimum_capacity
);
uint64_t mal_SymbolAdmission_capacity(const MalSymbolAdmission *admission);
uint8_t *mal_SymbolAdmission_data(MalSymbolAdmission *admission);
void mal_SymbolAdmission_reserve(
    MalContext *context,
    MalSymbolAdmission *admission,
    uint64_t minimum_capacity
);
MalType_Symbol mal_SymbolAdmission_finish(
    MalContext *context,
    MalSymbolAdmission *admission,
    uint64_t length
);
void mal_SymbolAdmission_drop(
    MalContext *context,
    MalSymbolAdmission *admission
);
```

`state`はruntimeだけが解釈し、zero状態はresourceを持たない。reserveはpointerを変更できるため、adapterはreserve後にdataを
再取得する。finishはbuilderをconsumeし、指定lengthの`Symbol`を返して元をzero状態にする。dropは未完了builderを解放し、
zero状態ではno-opとする。`minimum_capacity == 0`を認め、capacityが0ならdataはnullでよい。

hostが持つdata pointerは次のreserve、finish、dropのうち最初のoperationまでだけ有効で、capacity内へのwriteに限る。finish後に
pointer、builder state、storageを保持してはならない。lengthがcapacityを超えるfinishは有効なEngramを構成しないため、runtimeは
受理しない。allocation size overflowとallocation failureは現在のEngram constructionと同じくtrapする。

## authority

このoperationはExternからEngramへのadmissionである。extern operationはどのbytesとlengthをresultにするかを決めるが、bufferの
allocation、完成したdescriptor、immutability、到達可能性、回収はmalが支配する。構築中data pointerはadmission中だけの一時的な
write capabilityであり、完成した`Symbol`のidentityやlifetimeをhostへ渡さない。

外部allocatorが作ったbufferをそのままadoptするAPIは追加しない。adoptionはdeallocator、allocation identity、失敗時の回収、
aliasのcontractをhost側へ広げ、この変更の目的である一回のallocationとcopy除去に不要である。

## representation

builderのpublic carrierはruntimeだけが解釈するopaque stateを持つ。hostはhelperを通してdataとcapacityを一時観測する。
reference runtimeはbuilderを一意なflat `Symbol` allocationとして実装し、reserveで現在bytesを保ったまま幾何的に拡張できる。
finishはallocationをcopyせず通常のowned `MalType_Symbol`へ移す。

`loadSymbol`はlanguage primitiveとして外部regionからbytesをcopyする意味を維持する。builderはextern resultを構成するC adapter APIで、
source-level `Ptr`、mutable `Symbol`、allocator、stream型を追加しない。

## 理由

現在のtoken adapterはgrow可能なhost bufferを作った後、別のmal-controlled allocationへ全bytesをcopyする。短命tokenを大量に読む
workloadでは、sourceが直ちにbytesを観測して破棄しても二つのallocation領域とcopyを避けられない。

runtimeから構築中bufferを貸す方式なら、storage authorityをmalに保ったまま一方を除去できる。既知長のhost resultは一度のbeginで、
未知長のstream resultはreserveで同じcontractを利用できる。concat用flat allocationとcapacity growthも内部mechanismを共有できる。

## 採らない案

- 旧copy helperを互換layerとして残す: development ABIの調査面積と二つの推奨経路を残すため採らない。
- host bufferをadoptする: storageとdeallocatorのauthorityを不要にExternへ広げるため採らない。
- borrowed extern resultを`Symbol`として扱う: extern return後も成立するmal-owned valueを構成せず、admission規則に反する。
- source-level builderを追加する: 今回必要なのはtrusted adapter境界のmechanismであり、mutable Engramを言語へ追加する根拠がない。

検証順と性能上の位置づけは[generated program最適化計画](../../development/generated-program-optimization.md)を正とする。
