# D058. caller authorityが包含するparameter handoffはborrowする

- Status: Accepted
- Date: 2026-09-18
- Scope: backend非依存のexecution ownership planning
- Refines: D055, D057

## 問題

native callのcallerはcall完了までargument ownerを保持する。それでもcallee entryで常に`Share`し、callee exitで`Drop`すると、
read-only helperとrecursive controlの各遷移に同じretain/releaseが残る。特に`Packed` builderを運ぶproductでは、Region版にない
reference count操作がalgorithmの各stepへ入っていた。

一方、「同期callである」ことだけをfunction全体へ適用すると、self-tail、recursive dispatch、fresh closure、managed call resultを
同じ扱いにしてしまう。borrowed aliasだけを見て通常livenessからedge dropを再構成すると、aliasのlenderも見失う。

## 決定

`execution/ownership/parameter`はapplication target、call mode、recursive regionをauthorityとして、caller-boundedなfunctionとcall
siteを分類する。通常のnative ABI callはcallerがcall完了までauthorityを持つ。self-tailとrecursive regionは、到達する全functionが
managed bindingを`Atom`、product、sum以外から作らず、managed valueをreturnまたはcall resultとして受け取らず、region内siteの
possible targetが同じregionだけである場合に限り、外側のinvocation authorityを共有する。

この条件を満たすlive parameterはABI entryとowned control handoffの双方で`BorrowInto`する。使われないparameterはcallee側で
`Drop`しない。対応するcall argumentと、それを作るpureな`Atom`、product、sumは同じboundaryまでborrowする。fresh managed
operation、closure capture、managed returnその他の独立owner successorは従来どおり`Share`、`Consume`、`Drop`を使う。

borrow provenanceはlender dependencyをownership livenessへ閉じる。binding直後とedge上のdrop planはこの閉じたlivenessを唯一の
authorityとして使い、通常livenessから別のowner集合を再推論しない。

## 理由

parameter carrierはstorage lifetimeのauthorityではない。callerまたは外側のrecursive invocationが全pathを包含するときだけ、その
authorityを借りる表現が責任の実体と一致する。fresh managed valueやmixed dispatchがあるpathではauthorityが一意でなくなるため、
保守的にowner handoffを維持する。

call mode、possible target、managed operation、borrow provenanceを持つexecution stageがこの判断を所有する。LLVM backendやruntime
reference countからsource lifetimeを復元しない。

## 帰結

- read-only helperとbounded recursive controlはparameterごとのretain/releaseを持たない。
- `DirectSelfTail`はregion SCCが消去された後も同じboundedness検査を受ける。
- region外targetを含むdispatchとfresh managed authorityを作るrecursive controlはowned handoffを維持する。
- borrowed argumentがlocal ownerから作られた場合、そのlenderはcall終了edgeまでliveであり、そこで一度だけdropされる。
- wildcard、closure capture、first-class continuation、managed returnを含む実行testでallocation balanceを検証する。
