# D033. managed Engramをborrowとowned resultでlowerする

- Status: Accepted; failure classification superseded by D035; C backend placement superseded by D041
- Date: 2026-09-07
- Scope: reference C backend
- Supersedes: D008のmemory management節
- Refines: D031

## 決定

reference C backendはruntime storageを参照するEngramに型ごとのcopy/destroy operationを生成する。function parameterと
既存値の読取りをborrow、functionおよびruntime operationのresultをowned transferとし、保存時にretain、lexical scopeの
終了時にreleaseする。productとsumはmanaged fieldへこの規則を再帰適用し、closure environmentは最後のreleaseでcaptureを
destroyする。

最初の実装はlast-use解析を必須にせず、borrowを保存するときに保守的にretainする。move、escape analysis、region化はこの
規約を保つ最適化として後から追加できる。ropeやmemoizationはlifetime mechanismに含めない。

このretain/releaseはsource-level primitiveではなく、Engram authorityを実現するbackend operationである。Extern resource、
`Ptr`のreferent、external opaque handleには適用しない。この規約を引き継いだ現在のbackend規約は
[managed value ownership](../../implementation/ownership.md)に置く。

## 理由

program-lifetime arenaは正しいが、短命なSymbol連結やclosure environmentを反復ごとに保持する。source-level manual freeは
immutable aliasとaggregateに解放責務を露出し、malが持つEngramのlifetime authorityを利用者へ戻してしまう。

型付きIRではbinding、result、capture、aggregate fieldが既に明示されている。immutabilityによりalias作成時はreferentを
変更せずownership shareだけを増やせるため、borrow/result規約とlexical cleanupで安全な回収を局所的に生成できる。
GCのroot走査やtracing pauseを導入せず、最適化前でも使用量をlive valueへ概ね比例させられる。

## 帰結

- generated Cにはsourceに現れないretain/releaseが生じる。その位置と規約をimplementation documentで列挙する。
- managed aggregateのcopy costはmanaged field数に比例する。last-use moveは将来の測定に基づく最適化とする。
- reference countを循環させる値構築を将来導入する場合、cycleを別途扱う必要がある。現在のimmutable constructionと
  closure変換はmanaged valueから自己参照cycleを構築するprimitiveを提供しない。
- allocation failureとreference count overflowはmal trapになる。
