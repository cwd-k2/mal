# D048: 直和の構築をsum return binderに限定する

- Status: Superseded by D049

## 決定

source-levelの直和値は、その直和をresult型とするlambdaのsum return binderからだけ構築する。位置`i`のbinderを
適用すると第`i`項のpayloadを持つ直和値で現在のinvocationを完了する。`i[Sum]`と`Sum(i)`によるconstructor、ならびに
それらが作っていたfirst-class injection functionは廃止する。

```mal
Maybe :: [Unit, Int32];

none :: Unit -> Maybe := ()[none, some] { [none] };
some :: Int32 -> Maybe := (value)[none, some] { some(value) };
```

predefined `Bool` bindingも同じ意味へ統一する。

```mal
Bool :: [Unit, Unit];

false :: Bool := [()[cont0, cont1] { [cont0] }];
true :: Bool := [()[cont0, cont1] { [cont1] }];
```

第二の例にある外側の`[...]`はUnitをlambdaへ渡す通常のapplication、内側の`[cont1]`はUnitをreturn binderへ渡す
applicationである。lambda parameter groupを省略する別構文は追加しない。compiler内部ではsum return binderを既存の
sum injectionへlowerしてよく、source constructorの廃止はruntime representationを変更しない。

## 理由

直和の構築をreturn edgeの選択として一つの機構に集約すると、variant選択が現在のcontinuationを選ぶcontrolであることが
sourceに現れる。compile-time indexを受けるtype applicationと、そのためだけのsynthetic function valueが不要になる。
parameter group省略を加えないことで、lambda introducerも既存の一形式に保つ。

## 後継

`[k0, k1] { body }`を、value parameterを持つlambdaの省略形ではなく、その式のresult continuationだけを導入してbodyを
直ちに実行するCPS control expressionとするsyntaxは、lambda body内のformとして[D049](D049.md)で採択した。この式はUnitを受けずfunction valueも作らない。
期待result型が`[A, B]`なら`k0 : A`と`k1 : B`を導入し、lambdaのsum return binderと同じscope、arity、completion規則で
いずれかを選択する。

```mal
true :: Bool := [cont0, cont1] { [cont1] };
```

これは当時の構文`[()[cont0, cont1] { [cont1] }]`と同じ結果を持つが、Unit lambdaの生成と即時applicationではなく、
continuationだけを受けて直接選択するsource termとして定義する。D048の時点では新しいcontrol expressionを追加せず、
parameter groupとapplicationを明示していた。

## 置き換える判断

D042のsource-level sum injection constructorを置き換える。双方向application、continuationによるsum elimination、`if`は維持する。
現在の規範は[型](../../spec/types.md)、[明示的returnとcompletion](../../spec/control.md)、
[式とbinding](../../spec/expressions.md)、[字句と文法](../../spec/grammar.md)を正とする。
