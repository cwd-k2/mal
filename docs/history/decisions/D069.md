# D069. direct self-tail parameterをleaf handoffへrefineする

- Status: Accepted
- Date: 2026-09-20
- Scope: reference compiler

## 問題

`DirectSelfTail`はparameter aggregateをentry slotへ保存し、entry先頭で同じaggregateを再分解していた。LLVMはこのmemory round tripを
除去しても、back edgeでaggregateを再構築するため、変化しないfieldのidentity copyがhot loopに残った。これはsource semanticsや
control frameに必要な処理ではなく、loop-carried valueがaggregate handoffに隠れたtarget表現上のcostだった。

## 決定

execution planは、転送後のself-tail argumentとparameter patternのbinding対応、control use、ownershipを統合する。分解元aggregateが
後続で使われず、managed leafが全self-tail edgeで同じborrowed bindingを渡す純粋なentry prefixについてだけ、parameter leaf patternと
prefix長をadmitする。LLVM backendはadmit済みpatternを物理slotへ展開し、back edgeをprefix後のbasic blockへbranchさせて、LLVMの
mem2regとphi形成へloop-carried valueを公開する。backendは適用条件を再推論しない。

適用判定はsource名、特定の型、関数番号、workload shapeを参照しない。条件を満たさないfunctionは従来のaggregate handoffを使い、
空のLLVM optimization setでも同じprogramを実行できる。

## 帰結

- 変化しないself-tail parameter fieldのidentity copyをLLVMが除去できる。
- aggregate自体を返す経路や、変更されるmanaged fieldを持つ再帰はleaf化しない。
- semanticなfield同一性とadmit可能なentry prefixはexecution、物理slotとbranch表現はLLVM backendが所有する。
