# D049: direct blockとdirect result blockを導入する

Status: Accepted (2026-09-14). 直和除去のcontinuationに関する将来の議論は[D072](D072.md)で採択した

## 決定

`{ body }`をその場で評価するlexical block expression、`[k, ...] { body }`をlambda-local result continuationを
導入してその場で評価するdirect result blockとする。どちらもfunction valueを作らず、`() { body }`または
`[()[k, ...] { body }]`の省略とはしない。direct result blockは一つ以上のbinderと期待result型を必要とし、bodyの
fallthroughを認めない。

```mal
answer :: Unit -> Int32 := () {
    value :: Int32 := { base :: Int32 := 40; base + 1 };
    [done] { done(value + 1) }
};
```

compilerはdirect result blockを同じlambda内のtyped joinへlowerする。外側lambdaのreturn binderはblock内から利用できるが、
block自身のresult binderはnested lambdaへcaptureできない。top-level initializerは実行可能なblockを受け入れないため、
両構文を認めない。

## 理由

parameter、result continuation、どちらも導入しない計算を別のsource formとして区別すると、scopeとcontrol boundaryが
構文から読める。lambdaの即時applicationへ展開すると不要なfunction boundaryが入り、外側return binderのcapture拒否など
観測可能なstatic semanticsまで変わる。local joinとして定義すれば既存のcompletionとcontrol representationを再利用できる。

## 将来の議論

sum eliminationのcontinuation位置へbare blockを置く`result[{ body0 }, { body1 }]`は採択しないまま候補として残す。
これは`() { body }`の省略lambda、payloadを捨てるdirect branch、または一般のblock-to-function変換のいずれにも読める。
外側return binderへの到達、non-Unit payload、単一continuation application、expression armとの混在を一つの規則で
説明できてから判断する。現行ではcontinuationに従来どおりfunction expressionを明示する。

## 置き換える判断

[D048](D048.md)の将来候補を採択し、source-level sum constructionをlambdaまたはdirect result blockのsum binderに限定する。
continuation applicationとsum eliminationの既存規則は維持する。
現在の規範は[式とbinding](../../spec/expressions.md)、[明示的returnとcompletion](../../spec/control.md)、
[字句と文法](../../spec/grammar.md)を正とする。
