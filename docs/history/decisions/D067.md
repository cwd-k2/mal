# D067. recursive regionでcontrol storage viewをcacheする

- Status: Accepted
- Date: 2026-09-19
- Scope: reference LLVM backend、C runtime internal ABI

## 問題

D066でcontrol topをlocal SSAへ移した後も、frame pushはarena capacityとstorage pointer、popはstorage pointerをcontextから毎回読み直して
いた。control storageを変更するのはframe reserveとnested Mal functionだけなので、同じregion invocationの通常遷移にこの依存は不要である。

storage pointerを恒久的に不変とするとgrow後に旧allocationを参照する。C runtimeのarena layoutをLLVMから直接読むと、program固有の
frame loweringとprogram非依存のstorage mechanismの境界も越える。

## 決定

`backend/llvm/optimization/control_storage`はcontrol frameを持つrecursive regionのfunctionを選ぶ。選択されたfunctionはruntime getterで
得たstorage pointerとcapacityをlocal slotに保持する。capacity内reserveとpopはlocal viewを使う。capacityを越えるreserveは従来のruntime
helperを呼び、返されたstorageと現在capacityでviewを更新する。

control frameを持つ別のMal functionをnative callするとarenaがgrowし得るため、return直後に両方を再取得する。frameを持たないMal
function、region内branch、extern call、storageを変更しないruntime operationではrefreshしない。local viewのaddressはfunction外へ渡さず、
arena allocation、growth、overflowとfailureは引き続きC runtimeが所有する。baselineは各操作でruntimeからstorageを取得する。

## 帰結

- relocation後のpointerを使い、nested recursive regionが外側frameを上書きしない。
- 032の自然な再帰は60.23 msから54.62 msへ短縮した。
- 032のdata referenceは331,318,817から254,149,393へ23.3%減った。instructionは2.8%増えたため、採択理由はmemory dependency削減である。
- 029は151.12 msから142.75 msへ短縮した。
