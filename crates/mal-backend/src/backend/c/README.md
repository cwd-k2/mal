# backend/c

Generates the public C header and the host stub from `ProgramInterface`. The generated C shim that runs the LLVM
module lives in `backend/llvm/shim`.

| Module | Responsibility |
|---|---|
| `header`, `header/prefix` | generated header layout, include guard, portability macros, runtime ABI prefix |
| `host_signature` | host operation signatures |
| `types::TypeRegistry` | structural identity and C type mapping for the whole host interface |
| `types/collect` | postorder collection of host-visible representations from `ProgramInterface` |
| `types::HostTypes` | host-visible types reachable from externs and from aliases the checker admitted for canonical memory access |
| `types/host` | constructors, observers, and projections of host-mappable aggregates |
| `types/host/declaration` | type declarations needed by the host adapter and the public header |
| `types/host/memory` | unaligned-safe C read and write helpers derived from the shared canonical layout plan |
| `syntax` | typed C syntax nodes and their rendering, limited to the constructs the generated output uses |

## Construction boundary

Generators construct the restricted C syntax model and do not emit or reparse C source fragments. This includes
preprocessor replacement lists: line continuation is a rendering concern over structured items, not a reason to render an
item to text and split it back into lines. Clang remains the authority for C semantic validation; this model only represents
and validates the subset generated by the backend.

`c_function!`, `c_block!`, `c_statement!`, and `c_expr!` provide recursive construction syntax from function definitions
down to expressions and expand exclusively to the same typed nodes. A `rust` item embeds one already constructed node and an
`extend` item splices a runtime-generated statement, switch-case, or compound-literal initializer sequence without
rendering it. Rust retains
conditional, iterative, ABI, and host-mapping policy; the macros arrange the resulting nodes in C syntax order. Both
construction paths reach the same renderer and neither admits C source fragments.

`TranslationUnit` remains an imperative composition boundary because feature selection, section spacing, and declaration
ordering are stateful generation policy. Leaf declarations, signatures, parameters, and type names remain typed builders;
macros cover the recursively nested syntax whose constructor form otherwise obscures the generated C structure.
