# backend/c

Generates the public C header and the host stub from `ProgramInterface`. The generated C shim that runs the LLVM
module lives in `backend/llvm/shim`.

| Module | Responsibility |
|---|---|
| `header`, `header/prefix` | generated header layout, include guard, common helper templates, portability macros, runtime ABI prefix |
| `host_signature` | host operation signatures |
| `types::TypeRegistry` | structural identity and C type mapping for the whole host interface |
| `types/collect` | postorder collection of host-visible representations from `ProgramInterface` |
| `types::HostTypes` | host-visible types reachable from externs and from aliases the checker admitted for canonical memory access |
| `types/host` | constructors, observers, and projections of host-mappable aggregates |
| `types/host/declaration` | type declarations needed by the host adapter and the public header |
| `types/host/memory` | unaligned-safe C read and write helpers derived from the shared canonical layout plan |
| `syntax` | typed C syntax nodes and their rendering, limited to the constructs the generated output uses |

## Construction boundary

Generators construct the restricted C syntax model and do not emit or reparse C source fragments. This includes
preprocessor replacement lists: line continuation is a rendering concern over structured items, not a reason to render an
item to text and split it back into lines. Clang remains the authority for C semantic validation; this model only represents
and validates the subset generated by the backend.

Program-independent scalar memory helpers and aggregate expansion templates live in `mal.h`. File headers retain only the
structural or target-layout descriptors consumed by those templates. Descriptor replacement lists, statements, and switch
cases remain typed syntax nodes; compact output does not introduce an unvalidated C text path. One structural descriptor
supplies member names plus raw and host types to both representation definitions. Large descriptors are split into bounded
chunks before a shallow descriptor composes them.

Template macros cover types, declarations, aggregates, signatures, functions, blocks, statements, expressions, and
preprocessor directives. `#{ ... }` embeds one typed Rust node and `...#{ ... }` splices a runtime-generated node sequence.
Rust retains conditional, iterative, ABI, and host-mapping policy; the macros arrange nodes in C syntax order. Every path
reaches the same renderer and none admits C source fragments.

`TranslationUnit` remains the imperative composition boundary because feature selection, section spacing, and declaration
ordering are stateful generation policy. The shared notation and complete boundary are documented in
[`docs/implementation/backend-syntax-construction.md`](../../../../../docs/implementation/backend-syntax-construction.md).
