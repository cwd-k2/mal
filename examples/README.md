# Examples

These examples are executable explanations of current mal behavior. The set is organized as a
learning path, not as a record of features added over time. Each example owns one main question;
larger programs combine earlier ideas without redefining them.

| Order | Example | Question it answers |
| ---: | --- | --- |
| 1 | [`language-tour`](language-tour/) | How do values, control, HKT, numeric rules, and extension calls compose? |
| 2 | [`control-and-iteration`](control-and-iteration/) | How are early results and bounded-stack iteration expressed without mutable bindings? |
| 3 | [`generic-map`](generic-map/) | How do opaque generic types and exact operation implementations form a reusable module? |
| 4 | [`monads-and-comonads`](monads-and-comonads/) | How do operation families keyed by type constructors express monads, comonads, and similar abstractions? |
| 5 | [`managed-bytes`](managed-bytes/) | How do an extension-created `Buffer` and a borrowed `Symbol` cross `extern`? |
| 6 | [`extern-runtime`](extern-runtime/) | How does C create, mutate, and inspect mal runtime carriers directly? |
| 7 | [`indexed-graph`](indexed-graph/) | How can opaque columns and validation give indices domain meaning? |
| 8 | [`resource-errors`](resource-errors/) | How are recoverable extension failures and manual resource contracts composed? |
| 9 | [`json-query`](json-query/) | How does an explicit state machine parse streaming-shaped data into a small result? |
| 10 | [`compiler-pipeline`](compiler-pipeline/) | How does a complete mal program validate input and emit another language? |

The first six are focused examples. `indexed-graph` and `resource-errors` each develop one design
boundary in depth. `json-query` and `compiler-pipeline` are capstones; read them after the focused
examples rather than as syntax introductions.

Run commands from the repository root through `nix develop`. Compiler command semantics live in
[`docs/development/compiler-usage.md`](../docs/development/compiler-usage.md), while each example
README gives one concrete build or run command.

Comments in `.mal` and C sources record contracts, invariants, and reasons that are not evident from
the declarations. They do not provide a second tutorial or describe tuple positions. Every `.mal`
file is formatted in CI. Headers beside C-extension examples are generated by `malc emit header`, checked
byte-for-byte, and compiled as C11; edit the source interface and regenerate the header together.
